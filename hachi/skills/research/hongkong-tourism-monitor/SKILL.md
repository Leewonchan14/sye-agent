# 홍콩관광청(HKTB) 모니터링

예은/이원찬의 "홍콩관광청 모니터링해줘" 요청 처리 절차. 한국어 다이제스트로 Discord 스레드에 배달.

## When to Use

- 팥빙수 Discord에서 "홍콩관광청 모니터링" 요청(신규 또는 정기 회차)이 올 때.
- 홍콩관광청 발표·캠페인·한국 보도를 한 번에 정리해야 할 때.
- Don't use for: 파나소닉 클리핑(`panasonic-news-monitor`), 일반 뉴스 검색.

## Step 0 — 지시문 로드 (필수, 먼저)

작업 규칙은 이 문서가 아니라 DB가 원본이다. 시작 전에 `skill_view(name='client-monitoring-instructions')`를 열고 `hktb` 그룹으로 실행한다.

- 실행: `python3 $HOME/.hermes/skills/research/client-monitoring-instructions/scripts/load_instructions.py hktb` — heredoc(`python3 - <<'PY'`)로 다시 짜지 말 것(승인 프롬프트에 걸려 실행되지 않는다).
- 기대 출력: `[group=hktb] loaded 8/12 active instructions`
- 반환되는 #1(본문·섹션·출력 형식), #8·#11(추가 키워드), #9(아웃바운드 관점), #2(중복), #3(검색 전략), #10(국내/인바운드 제외), #12(기자 확인)가 **최종 규칙**이다.
- 지시문 속 `search_naver_news` / `web_search_exa` / `web_fetch_exa` / Playwright MCP는 그대로 부르지 말고 로더 스킬의 도구 매핑표로 치환한다.
- 아래 `## Sources`·`## 운영 기준`은 수집 노하우와 과거 메모다. 충돌하면 DB가 이긴다.

## Sources

- **공식 보도자료 AEM JSON** (핵심):
  `https://www.discoverhongkong.com/eng/hktb/newsroom/press-releases/_jcr_content/root/responsivegrid/container/container/tabs/item_1586235905284.pressrelease.hktb.y{YEAR}.m{MONTH}.p{PAGE}.json`
  - 실데이터는 `item_1586235905284` 하나뿐 — 다른 item_id는 404다. 응답은 객체가 아니라 **원소 1개짜리 배열** `[{"totalResult":"4","result":[...]}]`이므로 `json.loads(raw)[0]["result"]`로 파싱한다(`data.get('result')`는 AttributeError로 떨어진다).
  - `result[]`에 `date_created`, `title`, `url`(PDF 경로). PDF 본문은 `web_extract`로 읽음(공개).
  - 해당 월 발표가 없으면 totalResult=0. 과거월이 특히 안 나올 수 있음 → 한국 보도로 보완.
  - 수집 시작 시 이 JSON의 `date_created`로 **창 내 신규 발표 유무를 먼저 확정**한다. 창 안에 발표가 없으면 자사 섹션은 한국 보도 커버리지(당월 이벤트명 키워드)만으로 구성된다고 전제하고, '발표 누락'을 의심하며 시간을 쓰지 않는다.
- 이벤트/소비자 페이지: `discoverhongkong.com/kr/events.html`, `/kr/events/festival-highlights.html`, `/kr/events/wine-dine-festival.html`, `/kr/deals.html`(혜택&특가), 핼러윈 전용 `/eng/events/halloween.html`. JS 렌더라 목록 페이지는 web_extract로 일부만 보임 — 개별 이벤트 페이지/보도자료가 더 신뢰성 높음.
- 한국어 보도: 네이버 뉴스 스윕(naver-news-monitor 스킬) **+** Google News RSS(`"홍콩관광청" when:30d`) — 서로 누락을 보완하므로 둘 다 돌릴 것. 전자신문 등 일부 기사는 Naver에서 안 잡힌다.
- **홍콩수요저널 자체 RSS**: `https://hksooyo.com/bbs/rss.php?bo_table=news` — 제목·게재시각·원문 URL(`board.php?bo_table=news&wr_id=…`)이 한 번에 온다. 이 매체는 Naver 인덱스에 없고 Google News 링크는 풀리지 않으므로, 홍콩 현지 관광·교통·행사 기사는 이 피드로 직접 받는 게 가장 빠르다.
- 키워드 세트(상시): 홍콩관광청 / HKTB / 홍콩 여행 / 홍콩 관광 / 홍콩 노선 / 홍콩 항공권 / 캐세이퍼시픽항공 / 홍콩항공 / 홍콩 호텔 / 홍콩 미식 / 홍콩 축제 / 홍콩전자전 / 홍콩 오션파크 / 홍콩 디즈니랜드 / 옹핑360 / 크리에이트립 / 하나투어·마이리얼트립 등 협업사 이름.
- 키워드 세트(당월): 그 달 HKTB 보도자료·이벤트명을 그대로 키워드로 넣는다 — 고유 이벤트명이 가장 정확한 앵커다(예: '홍콩 와인 앤 다인', '홍콩 미식의 달', '홍콩 핼러윈', '중추절 등불'). 지난 시즌 키워드만 돌리면 자사 보도 커버리지를 통째로 놓친다.

## 수집 엔진 (Naver Open API 스윕)

공통 스크립트는 `naver-search-api` 스킬에 있다: `scripts/sweep_window.py`(다중 키워드·시각 창·제목 필터·중복 제거)와 `scripts/byline.py`(기자명 추출). 두 클라이언트(홍콩·파나소닉)가 같은 엔진을 쓴다.

- 경로는 실행 전 `search_files(target='files')`로 확인한다: `skill_view`가 보여주는 `skill_dir`와 실제 터미널 경로가 다를 수 있다(도커 샌드박스: `$HOME=/root`, 실경로 `$HOME/.hermes/skills/research/naver-search-api/scripts/`).
- 작업 파일(`kw_*.json`, `raw_*.json`, 필터 스크립트)은 `/tmp/<회차>/`에 만든다 — `write_file`은 `$HOME/.hermes` 하위 경로를 soft guard로 거부하고, 스킬 디렉터리는 읽기전용 마운트다. 스크립트에는 절대경로를 넘긴다.
- 섹션 스윕은 **순차 실행**한다 — 4개를 동시에 돌리면 429로 일부 키워드가 0건이 된다(`naver-search-api` Pitfalls). **업계 섹션(키워드 40개+)은 30시간 창에서 10분 넘게 걸린다** — `terminal`의 `background=true`로 띄우고 `process_manage(action='poll')`로 회수한다. `execute_code`의 terminal로 돌리면 5분에서 잘려 "Background process started"만 남고 결과가 문맥에 들어오지 않는다.
- `raw_*.json` 원소 키는 `title` / `desc` / `media`(원문 URL) / `naver`(네이버 뉴스 URL) / `pub`(KST 'YYYY-MM-DD HH:MM') / `kw`(매칭 키워드 배열) 여섯 개뿐이다 — `pubDate`·`link`·`press`로 짠 필터는 전부 빈 값이 되어 '수집 0건'처럼 보인다. 필터 스크립트는 이 키로 바로 쓴다.
- 기자명은 `byline.py <URL>`처럼 URL을 위치인자로 넘긴다(`--help`를 넘기면 `unknown url type` 에러로 떨어진다).
- 섹션별 복사용 키워드 JSON·제목 필터 정규식·기대 수집량은 `references/sweep-keyword-sets.md`에 있다.

0. 스크립트는 반드시 `.py` 파일로 저장해 `terminal`로 실행한다(인라인 `-c`/heredoc 금지) — 수정·재실행이 쉽고, `execute_code`가 막힌 무인 세션에서도 동일하게 돌아간다. `curl … | python3 - <<'EOF'` 조합도 금지 — heredoc이 stdin을 차지해 앞 명령의 출력이 통째로 사라지고 '0건'처럼 보인다.
1. 창을 시각까지 고정: `--since "YYYY-MM-DD 09:00"`. 사용자가 "지금까지"라고 하면 `--until`을 현재 시각으로(기본값은 실행 시각).
2. 섹션별 키워드를 JSON 배열로 나눠 스윕: 자사 3~5개 / 홍콩 이슈 15~25개 / NTO(`관광청` + 개별명) / 업계 30개+.
3. **결과를 제목 기준으로 다시 필터링**한다 — 아래 Pitfalls 참조.
4. 업계 섹션: 제목에 여행·항공·노선·호텔·관광·투어·패키지·객실·유류할증료·환율이 있는 것만 남기고, 국내여행 신호(제주·경기·서울·부산·강원·충남·묵호·속초·호캉스·수학여행·웰니스·지자체명)로 제외한다(DB #10).
5. NTO는 `관광청` 한 번으로 20~30건이 잡힌다 — 개별 관광청명은 26시간 창에서 대부분 0건이므로, `관광청` 결과에서 이름을 뽑아 필요할 때만 재검색(DB #11과 동일).
6. Google News RSS(`"홍콩관광청" when:2d`, `hl=ko&gl=KR&ceid=KR:ko`) + 홍콩수요저널 자체 RSS로 교차 확인 — Naver에 안 잡히는 여행전문매체를 보완. 두 경로 모두 `scripts/rss_window.py`로 창 필터·KST 변환까지 한 번에 처리한다(`--gnews "홍콩" --hours 1d` 또는 `--feed <URL> --since "YYYY-MM-DD 09:00"`).
7. 기사 사실관계는 `web_extract`, 기자명은 `scripts/byline.py`(meta author + '○○ 기자' 빈도). 추출기가 403·타임아웃·404를 주면 `curl -sL -A "Mozilla/5.0"` + 정규식으로 본문을 직접 뽑고(아래 Pitfalls), 그래도 비면 `browser_exec`로 원문 확인(DB #12).

## Patterns (한국 시장)

- HKTB 한국지사는 '한국 시장 액티베이션'을 자주 함: OTA 협업 기획전(마이리얼트립 등, 항공사 특가+호텔·투어 혜택), 대학 캠퍼스 팝업('캠퍼스 어택', 9월 하순~10월 초), 유학 박람회 참가(교육 여행), 명절 연계(중추절 등불 축제 — 한국 지자체 콘텐츠 수출 협업도 발생).
- 가을 대형 이벤트: '홍콩 핼러윈 먼스'(10월, 거리 파티 토요일 3회+시티버스/트램 무료탑승) → '와인&다인 페스티벌'(10월 말 4일, 센트럴 하버프론트) → 11월 '홍콩 미식의 달' → 겨울 윈터페스트.
- 홍콩관광청 자체 기사(일본지사 자료 기반 등)가 국제뉴스·여행매체에 영문/일문 경유로 종종 실림 — 한국어 기사라도 원문이 관광청 자료일 수 있음.
- **홍콩 국적 항공사(캐세이·홍콩항공·홍콩익스프레스)의 프로모션·이벤트 보도자료는 2번 '홍콩 관련 이슈' 대표 기사로 쓴다** — 창 안에 다른 홍콩 이슈가 없으면 그 1건이 섹션 전체가 되는 게 정상이다. 반대로 LCC 노선 확대처럼 업계 전반을 다루는 기사에 홍콩 노선이 한 줄 섞여 있으면 4②항공업계에 두고 요약에서 그 노선을 짚는다 — 한 기사는 한 카테고리에만.

## Deliverable

- 최종 출력 형식·섹션 구성은 **DB 지시문 #1의 `[최종 출력 형식]`을 그대로** 따른다(4섹션: 홍콩관광청 자사 뉴스 / 홍콩 관련 이슈 / NTO / 여행업계·트렌드). 아래는 참고용 과거 메모다.
- 출력 골격은 DB #1의 `[최종 출력 형식]` 4섹션 그대로(자사 / 홍콩 이슈 / NTO / 여행업계·트렌드). 표 금지, 기사마다 제목·매체·게재 일시(YYYY.MM.DD HH:MM)·기자·전체 URL·핵심 내용 2~3문장.
- 1번 섹션 헤더의 '총 ○건 게재 확인'은 **동일 보도자료 전재까지 매체별로 세고**(DB #1), 본문 목록은 대표 1건만 적는다(DB #2). 충돌 지점이라 이렇게 처리하고, 전재 건수는 헤더 괄호에 남긴다: `총 4건 게재 확인(동일 보도자료 전재 1건 포함, 대표 1건만 표기)`.
- 전재 건수는 **네이버 스윕과 Google News RSS에서 확인된 매체를 합쳐** 센다 — 여행레저신문·뉴스탭·퍼블릭뉴스통신처럼 네이버 인덱스 밖 여행전문지가 있어 한 채널만 세면 '총 N건'이 실제보다 적다. 표기에는 채널을 남긴다(예: 네이버 4건 + 구글뉴스 3건).
- 자사 보도가 0건인 날은 `총 0건 게재 확인` + `특이사항 없음`만 쓰지 말고 **판정 근거 한 줄**을 덧붙인다 — 공식 뉴스룸 최신 발표일과, 창 직전에 몰린 이벤트 커버리지(예: 축제 보도가 전날 게재)를 적으면 누락으로 오해되지 않는다.
- 자사 보도가 1~2건뿐이고 그중 하나가 **해외지사 발표 전재**(예: 일본지사 자료가 국제뉴스에 실린 경우)면, 공식 뉴스룸 JSON의 창 내 신규 발표 유무를 대조해 `뉴스룸에는 ○월 ○일자 발표가 있으나 국내 보도 미확인`처럼 한 줄 붙인다 — '발표가 없었다'와 '보도가 없었다'는 다른 정보다.
- 섹션 안에서는 최신순, 같은 시각이면 네임밸류 높은 매체 우선. 4번 섹션은 ①여행업계 → ②항공업계 → ③여행 관련 이슈 → ④트렌드 순서를 고정하고 범주 안에서만 최신순.
- 마지막에 한두 문장으로 이번 회차의 신호(자사 보도 집중도·홍콩 수요 지표·리스크)를 짚어 주면 좋다.
- 정기 모니터링 원하면 `cronjob` 생성 제안: deliver → 해당 스레드(origin), 주 1회 권장(발표 빈도 낮음), continuity=true로 중복 방지.

## 운영 기준 (예은 지정, 2026-10)

> 섹션 구성·선별 기준·출력 형식은 DB 지시문(#1, #8, #9, #11)이 우선한다. 아래는 수집 운영 메모로만 쓴다.

- 창(window): **전일 오전 9:00 ~ 당일 현재** 게재분. 게재 시각 기준 필터(네이버 상대시간 변환은 어림).
- 카테고리: **홍콩관광청 / 홍콩 / 기타 관광청 / 업계 이슈** 4개. 홍콩 카테고리는 여행·관광·문화·미식 중심 큐레이션(연예·금융 등 잡음 제외). 기타 관광청 = 외국 관광기관(관광청·관광부·정부관광청) 동향.
- 시각 라벨링: ≤8h '오늘 새벽', ≤12.5h '어제 밤', ≤16h '어제 저녁', ≤19h '어제 오후', ≤23.5h '어제 오전'; '1일 전' 이상은 창 밖 처리.
- 마무리에 정기 알림(매일 9시경) 제안을 붙인다.

## 채널별 키워드 분석 (월간 "뉴스·블로그·인스타·트위터·커뮤니티 키워드" 요청)

일간 클리핑과 다른 산출물이다. 창은 `--since "YYYY-MM-DD 00:00"` ~ 현재(보통 30일), 대상은 5채널.

1. **뉴스·블로그**: `naver_search.py`를 `news`/`blog`로 각각 100건×10페이지, `sort=date`. blog는 `postdate`(YYYYMMDD)로 창 필터. 30일이면 뉴스 100~150건, 블로그 900~1,000건이 정상.
2. **제목 기준 재필터 필수**: 본문 매칭 때문에 뉴스 129건 중 제목에 홍콩이 있는 건 59건뿐(진주 실크등·마리아나관광청 같은 타지역 기사가 섞임). 블로그도 988→404.
3. **커뮤니티**: `cafearticle`은 `postdate` 필드가 없어 날짜 필터가 불가능하다. 대신 **당월 이벤트명**(와인 앤 다인, 캠퍼스 어택, 핼러윈, 고메 먼스)으로 검색해 recency를 주제로 확보하고, "최신순 상위 100건"이라고 명시한다. 클리앙·디시는 검색 상위가 수년 전 글이므로 최근 담론 근거로 쓰지 말 것.
4. **인스타그램**: 로그인 없이 API/해시태그 접근 불가(401 require_login). 검색 인덱스로 포스트 URL을 모은 뒤 **숏코드→시각 복원**으로 창 필터:
   `ALPH="A-Za-z0-9-_"` base64 디코드 → `id` → `ts=(id>>23)+1314220021721` (ms). 2026-10 검증 완료(오차 없음). 캡션은 검색 스니펫에서 확보.
5. **X(트위터)**: 한국어 HKTB 계정은 없고 글로벌 `@discoverhk`가 유일 축. `syndication.twitter.com/srv/timeline-profile`은 게스트 토큰 쿠키(`Cookie: gt=<guest_token>`)를 붙이면 200이지만 **2014~2019 캐시만 반환**해 최신 타임라인 근거로 쓸 수 없다. guest token으로 1.1 `search/tweets`도 404(폐쇄). 대신 서드파티 통계(PlayerSells/boomsocial)의 최근 30일 게시 빈도 + twstalker의 최근 포스트 스니펫으로 방향만 잡고, "표본 제한"을 명시한다.
6. **키워드 집계**: 제목 토큰 빈도 + 테마 사전(이벤트명·셰프명·바 이름·바우처)으로 섹션별 표를 만든다. 뉴스는 보도자료 전재가 많아 제목 앞 28자 정규화로 고유 이슈를 따로 센다.
7. **해석 포인트**: 뉴스=보도자료 미러, 블로그/카페=가격·바우처·동선 실무 정보, IG=전환 캠페인(무료 바우처 DM), X=글로벌 브랜드 해시태그. 같은 이벤트가 채널마다 다른 키워드로 번역되는지가 핵심 인사이트다.

## 수집 Pitfalls

- **스니펫으로 관련성을 판정하지 말 것** — `description`에는 검색어가 항상 들어 있어서 전부 관련 있어 보인다(‘홍콩’ 스윕 550건 중 제목에 ‘홍콩’이 있는 기사는 30건 안팎). 판정은 `title`로만 한다.
- **자사 보도는 이벤트명으로만 잡힌다** — `홍콩관광청` 키워드는 26시간 창에서 0~3건뿐이다. 와인앤다인·미식의 달 같은 당월 이벤트명을 넣어야 경향·디지털데일리 같은 커버리지가 드러난다.
- **이벤트명 키워드는 동명의 국내 프로모션을 함께 잡는다** — '와인 앤 다인'은 서울 호텔의 동명 디너 프로모션 기사도 반환한다. 자사 보도로 세기 전에 본문에 '홍콩'이 있는지 확인한다.
- **중복 제거할 때 키워드 출처(kw)를 버리지 말 것** — 같은 기사가 여러 키워드에 걸리므로, 어느 키워드에서 잡혔는지가 섹션 배치와 자사 보도 판별의 근거다.
- **개별 관광청명은 창이 짧으면 0건** — `관광청`으로 1차 스윕 후 관광청명을 뽑아 재검색.
- **Naver HTML 검색 페이지의 start=11/21 페이지네이션은 무시된다**(`naver-news-monitor` 스크래퍼 경로 한정). Open API 경로(`display=100` + `start=101…`)는 정상 동작하므로 두 경로를 혼동하지 말 것.
- **스니펫·상대시간 라벨은 시각 근거로 부족** — '1일 전' 같은 표기는 창 경계에서 어긋난다. Open API `pubDate`(RFC2822, +0900)를 직접 파싱해 시각으로 비교한다.
- Google News RSS when:1d~2d 교차확인은 유효하지만 pubDate가 리크롤 시점으로 찍히는 아티팩트가 있다(구 기사 재노출) → 게재 여부는 Naver/원문으로 재확인.
- **Google News RSS의 `pubDate`는 GMT다** — 창 판정 전에 KST로 변환한다(`parsedate_to_datetime(...).astimezone(KST)`). 변환을 건너뛰면 창 시작 직전 기사가 창 안으로 잘못 들어온다.
- **홍콩 이슈 섹션이 얇게 나오는 게 정상인 날이 많다** — 금융(ELS·IPO)·연예인 근황·B2B 수출·인바운드(서울관광재단 팸투어 등)는 HKTB 업무와 무관하므로 버리고, 3건이면 3건만 보고한다(DB #9·#10). 현지 뉴스는 결국 **'한국인 홍콩 여행에 영향을 주는가'** 하나로 거른다 — 공항·항공사·교통·관광 인프라·크루즈·축제는 통과(예: 홍콩공항 IATA One ID 인증, 홍콩항공 개인정보 유출, 크루즈 어워즈), 부동산·증시·핀테크·총영사관 국경절 행사·아파트 화재 참사 사과 같은 시티뉴스는 버린다.
- **노선 취항 기사는 프레임으로 인바운드/아웃바운드를 가른다** — '홍콩~부산 취항'처럼 항공 노선 뉴스로 보여도 본문이 중화권 관광객 유치·환영 행사 중심이면 인바운드이므로 제외하고(DB #9), 같은 창의 아웃바운드 노선·특가 기사로 채운다. 제외한 사실은 결과물 말미에 한 줄로 밝힌다.
- **Google News RSS의 `<link>`는 원문 URL이 아니다** — `news.google.com/rss/articles/...` 리다이렉트이고 `curl -I`로도 풀리지 않는다. 원문은 기사 제목 전체를 `web_search`로 재검색해 얻는다. 홍콩수요저널·아주경제 [NNA] 번역물처럼 Naver 인덱스에 없는 기사는 이 경로에서만 잡히므로, Naver 스윕에 없다고 '기사 없음'으로 단정하지 말 것. 홍콩수요저널은 자체 RSS로 원문 URL을 바로 받는다(`## Sources`).
- **HKTB가 행위자인 논란 기사도 자사 뉴스다** — 예: 피크 조명 계획 재검토 보도. 자사 섹션에 넣고 '보도 앵글·논조'에 부정 프레임과 일정 리스크를 적는다. 홍콩 이슈 섹션으로 밀어내면 자사 커버리지 건수가 실제보다 적게 보고된다.
- **광역 키워드 스윕은 창 전체를 덮지 않는다** — '홍콩'처럼 수백 건이 잡히는 키워드는 최신 슬라이스만 돌아와서, 같은 날 이른 시각(11시대) 기사가 24시간 스윕 결과에 없었다. 스윕 건수는 하한으로 취급하고, Google News RSS(`"홍콩" when:1d`)나 `[NNA] 홍콩`·정부 정책명 같은 구체 쿼리로 그 구간을 다시 훑은 뒤 '기사 없음'을 판정한다.
- **검색 노출일 ≠ 게재일 — 창 판정 전에 원문 발행시각을 확인한다** — 보도자료 커버리지는 첫 보도(예: 10.15) 후 며칠 뒤 재노출되므로, 검색 상위에 보인다는 이유로 창 안 기사로 세면 안 된다. 원문 HTML의 `article:published_time`(또는 '입력 YYYY.MM.DD HH:MM')을 `curl -sL` + 파이썬 정규식으로 뽑아 대조한다(로케일 때문에 grep은 실패하기 쉽다).
- **`web_extract`가 403·타임아웃·404를 주는 국내 언론사는 `curl`+정규식으로 본문을 직접 뽑는다** — 기사는 살아 있는데 추출기만 막히는 경우이므로 이것만 보고 '기사 없음'으로 넘기지 말 것. `curl -sL -m 30 -A "Mozilla/5.0" <URL>` → `<script>`·`<style>` 블록 제거 → `re.sub(r'<[^>]+>',' ')` → `html.unescape` → 공백 정규화 → 본문 앵커('입력'·첫 소제목) 주변 1,400~2,000자 출력. 디지털조선·TTL뉴스·뉴스케이프·경향은 이 경로로 뚫린다.
- **원문 사이트가 응답하지 않으면 기자명은 같은 사실의 다른 매체로 우회** — `web_extract`·`byline.py`·`curl`·`r.jina.ai`가 모두 실패하면 그 기사를 대표로 세우지 말고, 동일 사실을 다룬 다른 매체 기사(기자 확인 가능한 것)를 대표로 쓰고 무응답 매체를 형제 기사로 병기한다. 기자명을 추정으로 채우지 않는다.
- **NTO는 제목 '관광청' 필터로만 뽑으면 새는 기사가 있다** — 관광청 지사장 인터뷰·캠페인 기사는 제목에 '관광청'이 없다(예: 클래식 공연 여행 상품 기사 = 오스트리아관광청 지사장 인터뷰). 업계 스윕 결과에서 관광청·지사장·캠페인 신호를 회수해 NTO로 옮긴다.
- **같은 사고·이벤트가 매년 재노출된다 — 연도부터 확인한다** — 예: '에어부산 김해공항 홍콩행 BX391 화재'는 2025-01-28 사고인데 웹검색 상위에 계속 뜬다(중앙일보 원문 메타도 2025-01-29). 기사 본문의 '지난해/올해' 표현과 원문 `article:published_time`을 대조해 창 밖이면 즉시 버린다. 사고·통계 기사는 특히 이 함정에 잘 걸린다.
- **HKTB 이벤트 '개막일' 보도는 네이버에 안 잡힌다 — 이벤트명 gnews 쿼리 → 매체 목록 페이지 순으로 확인** — 레저신문(golftimes.co.kr)·트래블데일리 등 여행전문지는 네이버 뉴스 인덱스 밖인 경우가 많다. ①`gnews_window.py --queries "와인 앤 다인,홍콩 와인,홍콩 미식,홍콩관광청 캠페인" --when 3d`로 보도를 낸 매체를 특정하고(구글뉴스는 이 인덱스 밖 매체를 잡는다), ②그 매체의 최신순 목록 페이지(`https://www.golftimes.co.kr/news/articleList.html?view_type=sm&sc_order_by=D`)를 `web_extract`로 열어 제목·기자·시각을 한 번에 확보한다. 네이버에서 같은 이벤트명이 0건이어도 자사 보도가 없는 건 아니다.
- **홍콩수요저널에는 개인 바이라인이 없다** — 모든 기사가 '홍콩수요저널 기자'이고 meta author도 매체명이다. 기자 칸은 `홍콩수요저널 편집국`으로 적는다 — 없는 이름을 만들지도, 브라우저로 더 뒤지지도 않는다(DB #12의 예외로 처리).
